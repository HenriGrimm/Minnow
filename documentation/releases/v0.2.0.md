# Minnow 0.2.0

Minnow 0.2.0 brings one agent and one permission level across the workspace, saved agent conversations, an issue-to-review workflow, smarter model routing, and live phone access. This release collects the changes since **0.1.13**; the stable version jumps directly to **0.2.0**.

## Highlights

- **One agent, fewer switches.** Every chat uses the same assistant and tools. Use `/ask`, `/plan`, and `/debug` for focused workflows instead of changing composer modes.
- **One permission level.** Manual, Auto (default), and Full access govern tools, commands, browser actions, MCP, plugins, and delegated work. Change the level from the composer or Settings.
- **Work from issue to delivery.** Dashboard and Issues bring linked chats, worktree setup, changed-file review, commits, and merges into the project workflow.
- **Keep up with agent work.** Delegated agents have saved conversations, live transcripts, input requests, and durable completion handoffs. Inspect their work and continue the conversation.
- **Choose models by task.** Unified model pickers, task-aware pools, quota-aware routing, reasoning controls, and provider account usage make model selection clearer.
- **Take your workspace with you.** Connect a phone or tablet over your home network or through built-in Tailscale access, then follow live chats, send instructions, and stop work.

## Chats and agent execution

- Supported new and idle ordinary chats execute on the server, with live updates shared across windows and connected devices. Unsupported historical workflows retain their compatibility path.
- Messages show immediate sending feedback while drafts and attachments remain recoverable until acknowledgement. Mid-run steering appears in the transcript; queueing for later stays separate.
- Improved parent/child completion delivery, interruption recovery, saved tool groups, reasoning summaries, elapsed work time, and transcript scrolling. A delivered negative assessment is a completed review, not a crashed agent to retry.
- Added follow-up suggestions, an attention inbox, and clearer activity and question presentation. Delegated-chat and wait-tool completion alerts are quieter.
- Improved image delivery, attachment retention, context budgeting, compaction, and last-request token accounting for CLI providers.
- Reduced repeated catalog discovery, whole-chat saves, polling overlap, reasoning renders, and Git snapshot work. Independent CLI read tools can run in batches.

## Project workflow and Source Control

- Code is the default project surface. Dashboard brings goals, issues, agent activity, review, and delivery together.
- Start linked agent work from Issues, optionally prepare an isolated worktree and dependencies, review the resulting diff, and commit or merge from the work panel.
- Added one-click chat worktrees and clearer setup failures and retry controls. npm workspace worktrees install their own dependencies instead of resolving against another checkout.
- Changed-file records retain their Git branch and checkout, so reviewing older work does not silently open a same-named file from another branch.
- Improved remote branch selection, batch change selection, conflict recovery, pasted issue attachments, GitHub parent restoration, and rate-limit handling.
- Added line-range navigation from file search, Markdown file-reference links, agent file handoff cards, and a `/kickoff` project setup skill.

## Models and integrations

- Added task evaluation and task-aware model pools, quota-aware routing and recovery, provider account usage inspection, and clearer reasoning-effort selection.
- Improved live CLI model discovery, inline browser sign-in, Claude tool handoffs, Cursor ACP recovery, Codex continuity, and question handoff handling.
- Added MTPLX runtime visibility and board reasoning controls.
- Added an opt-in Agent Browser integration using native Electron tabs.
- The Codex native-coding experiment remains **off by default** and limited to the verified Windows Codex 0.166.0 / gpt-5.5 configuration. Other versions, platforms, and models are not certified for native execution.

## Phone access, reliability, and safety

- Added a dedicated phone interface with QR pairing, a workspace picker, live chat controls, and home-network or Tailscale connectivity. The desktop must remain running and reachable.
- Revoking device access disconnects active streams and sockets. Workspace switches expire stale phone screens and pending edits.
- Hardened isolated previews, remote routes, workspace boundaries, physical Plan-directory checks, archive extraction, and shared file mutations.
- Improved backup/restore journaling, corrupt-session recovery, config-write durability, encryption-key creation, interrupted voice downloads, and Windows file-lock handling.
- Turn undo preserves staged and working-tree content separately. Workspace switching guards unsaved editor drafts, and file creation/moves refuse accidental replacement.
- Improved board recovery, cancellation ownership, terminal/process teardown, preview occlusion, and Windows updater relaunch behavior.
- Brain knowledge and code indexes are isolated by canonical checkout; the Brain graph no longer has its previous node cap.

## Upgrading from 0.1.13

- **Review permissions after upgrading.** The global permission level replaces per-tool Ask/Full/Off controls and persistent browser-origin grants. Existing per-tool maps are not the authority. Chat-specific approval grants last only for that chat.
- **Use slash workflows instead of composer modes.** `/ask` is read-only; `/plan` permits plan-document edits but not application-code edits. Saved legacy mode identifiers remain loadable.
- **Full access applies to connected devices too.** Choose it deliberately. The global permission level is not an operating-system sandbox; shell containment is a separate setting.
- **Back up important work first.** Use Settings backups and commit project changes before a long unattended run.
- Server execution does not imply complete historical-chat parity. Some history-editing and replay operations remain unavailable for agent conversations or unsupported histories; continue with a new message when an action is guarded.
