# Minnow 0.2.0

Minnow 0.2.0 simplifies agent controls, connects issue work to review and delivery, and improves chat responsiveness and recovery. It also adds task-aware model routing and a dedicated phone interface.

This release collects the changes since **0.1.13**, jumping directly to **0.2.0**. Existing features such as saved agent conversations are improved—not new to this release.

## Highlights

- **One agent, fewer switches.** Chats use the same assistant and tools. `/ask`, `/plan`, and `/debug` provide focused workflows instead of separate composer modes.
- **Simpler permissions.** Manual, Auto (default), and Full access replace per-tool permission controls with one level across commands, file tools, browser actions, MCP, plugins, and delegated work.
- **Issue-to-delivery workflow.** Dashboard and Issues bring linked chats, isolated worktree setup, changed-file review, commits, and merges together.
- **Better agent coordination.** More reliable completion handoffs, clearer questions and activity, immediate steering feedback, and improved interruption recovery build on existing saved conversations.
- **Task-aware model selection.** Unified pickers, task evaluation, model pools, quota-aware routing, and provider account usage help you choose and manage models.
- **A dedicated phone experience.** QR pairing and home-network or Tailscale access let you follow live chats, send instructions, and stop work from a phone or tablet.

## Chat and agent improvements

- Supported new and idle ordinary chats run through the server, sharing live updates across windows and connected devices. Unsupported historical workflows retain their compatibility path.
- Sending shows immediate feedback. Drafts and attachments remain recoverable until the send is acknowledged, and mid-run steering appears in the transcript separately from queued follow-ups.
- Improved parent/child result delivery, interruption recovery, saved tool groups, reasoning summaries, elapsed work time, and transcript scrolling. A completed review with negative findings no longer looks like a crashed agent that should be retried.
- Added follow-up suggestions and an attention inbox, with clearer question and activity presentation and quieter delegated-chat and wait-tool completion alerts.
- Improved image delivery, attachment retention, context budgeting, compaction, and CLI last-request token accounting.
- Reduced repeated catalog discovery, whole-chat saves, overlapping polling, reasoning renders, and Git snapshot work. Independent CLI read tools can run in batches.

## Dashboard, Issues, and Source Control

- Code is the default project surface; Dashboard brings project goals, issues, agent work, review, and delivery together.
- Start linked work from Issues, optionally prepare an isolated worktree and its dependencies, inspect the resulting diff, then commit or merge from the work panel.
- Added one-click chat worktree setup, clearer dependency failures, and retry controls. npm workspace worktrees install their own dependencies rather than resolving against another checkout.
- Changed-file records retain their branch and checkout, preventing older work from opening a same-named file on the wrong branch.
- Improved remote branch selection, batch change selection, conflict recovery, pasted issue attachments, GitHub parent restoration, and rate-limit handling.
- Added file-search line-range navigation, Markdown file-reference links, agent file handoff cards, and a `/kickoff` project setup skill.

## Models and integrations

- Added task evaluation, task-aware model pools, quota-aware routing and recovery, and broader provider account usage inspection.
- Improved reasoning-effort selection, live CLI model discovery, and inline browser sign-in.
- Improved Claude tool handoffs, Cursor ACP recovery, Codex continuity, and CLI question handling.
- Added MTPLX runtime visibility and board reasoning controls, plus an opt-in Agent Browser integration using native Electron tabs.

## Phone access, reliability, and safety

- Added a dedicated phone interface with QR pairing, a workspace picker, and live chat controls over a home network or Tailscale. Your desktop must remain running and reachable.
- Disconnecting a device revokes its active streams and sockets; switching projects expires stale phone screens and pending edits.
- Hardened isolated previews, remote routes, workspace boundaries, Plan-directory checks, archive extraction, and concurrent file edits.
- Improved backup/restore journaling, corrupt-session recovery, config writes, encryption-key creation, interrupted voice downloads, and Windows file-lock handling.
- Turn undo preserves staged changes separately from working files. Workspace switching protects unsaved editor drafts, and file creation and moves refuse accidental replacement.
- Improved board recovery, cancellation ownership, process teardown, preview occlusion, and Windows updater relaunch behavior.
- Brain knowledge and code indexes are isolated by canonical checkout; the Brain graph's previous node cap has been removed.

## Upgrade notes and current limits

- **Review your permission level.** The global level replaces per-tool Ask/Full/Off settings and persistent browser-origin grants. Chat-specific approval grants last only for that chat.
- **Full access also applies to connected devices.** Choose it deliberately. Shell containment remains a separate setting; the permission level is not an operating-system sandbox.
- **Use slash workflows instead of composer modes.** `/ask` is read-only; `/plan` permits plan-document edits but not application-code edits. Saved legacy mode identifiers remain loadable.
- **Back up important work before upgrading.** Use Settings backups and commit project changes before long unattended runs.
- Server execution does not mean complete historical-chat parity. Some history-editing and replay actions remain unavailable for agent conversations or unsupported histories; continue with a new message when an action is guarded.
- The **Codex native-coding experiment remains off by default**, limited to the verified Windows Codex 0.166.0 / gpt-5.5 configuration. Other versions, platforms, and models are not certified for native execution.
