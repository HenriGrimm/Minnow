# MIN-262 — Use displayed task titles for Orchestrator Board git commits

**Date:** 2026-09-15
**Goal:** Board-generated git commits carry the task title the board displays (`W1-A: <title>`) instead of role/taskId stubs (`builder W1-A pass`, `merge W1-A`).
**Granularity:** medium

## Context

When an Orchestrator Board runs, the engine generates git commits on the board's behalf in two places:

1. **Per-attempt worktree commit** — `finishAgent` in `server/orchestrator/effector-runner.js:586` commits a passing builder/tester attempt's worktree with `` `${desired.role} ${desired.taskId} pass` `` (e.g. `builder W1-A pass`).
2. **Integration merge commit** — `runMerge` in `server/orchestrator/merge-queue.js:248` merges the task branch into the integration worktree with `` `merge ${taskId}` `` (e.g. `merge W1-A`).

Neither uses the task title the board renders. The board card displays `task.id` + `task.title` (`src/orchestrator/board-render.ts:421`), and `TaskState.title` (`server/orchestrator/core/types.d.ts:293`) is always populated from the plan's `#### Task W1-A: <title>` heading. Both call sites already have access to `BoardState` (`finishAgent` via `currentState()`, `runMerge` via its `state` parameter), so no plumbing changes are needed.

**Format decision:** use `` `${taskId}: ${title}` `` (e.g. `W1-A: Add login form`). This keeps the commit traceable to the board card (which shows id + title together) while using the displayed title verbatim. Fallback when the title is missing/blank: the bare task id. Alternative considered — title only — was rejected because it loses the id↔commit link the board UI relies on.

**Explicitly out of scope:** the board-level landing commit in `src/orchestrator/board-report.ts:833` (`feat: <planName> (orchestrate board <boardId>)`) — that is the whole-board commit, not a task commit. The defensive fallbacks `'Board attempt'` (`server/orchestrator/worktree-lifecycle.js:450`) and `'Board task commit'` (`server/worktree/worktree-ops.js:540`) stay as-is; both board callers will now always pass an explicit message.

## Wave Breakdown

### Wave 1 — Shared commit-title helper

#### Task W1-A: Add `taskCommitTitle(state, taskId)` to `worktree-lifecycle.js`
- **Build:**
  - In `server/orchestrator/worktree-lifecycle.js`, add an exported function next to the other task-keyed helpers (e.g. after `slotIdForTask`):
    ```js
    /**
     * Commit subject for a task's work: the title the board displays,
     * prefixed with the task id so history maps back to the board card.
     * Falls back to the bare task id when the title is missing.
     * @param {import('./core/types').BoardState | null | undefined} state
     * @param {string | null | undefined} taskId
     * @returns {string}
     */
    export function taskCommitTitle(state, taskId) {
      const task = state?.tasks?.get(String(taskId ?? ''));
      const title = typeof task?.title === 'string' ? task.title.trim() : '';
      return title ? `${taskId}: ${title}` : String(taskId ?? 'board task');
    }
    ```
  - Do not change `commitAttemptWorktree`'s `'Board attempt'` default — callers now always pass a message.
- **Test:** In `test/orchestrator/worktree-lifecycle.test.mjs`, add a pure unit test (no git needed) that builds a state via the existing `boardState(['W1-A'])` helper **with a distinct title** (extend `taskSpec` to accept an `extra` object, e.g. `taskSpec('W1-A', { title: 'Alpha task' })`) and asserts:
  - `taskCommitTitle(state, 'W1-A') === 'W1-A: Alpha task'`
  - `taskCommitTitle(state, 'missing') === 'missing'` (fallback)
  - `taskCommitTitle(state, null) === 'board task'` (fallback)
  - title with surrounding whitespace is trimmed.
- **Accept:** `taskCommitTitle` is exported from `server/orchestrator/worktree-lifecycle.js` and the new unit test passes under `node --test test/orchestrator/worktree-lifecycle.test.mjs`.
- **Touches:** `server/orchestrator/worktree-lifecycle.js`, `test/orchestrator/worktree-lifecycle.test.mjs`
- **Depends on:** (none)
