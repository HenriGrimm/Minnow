# MIN-373 — Issues app badge must count only the current workspace's issues

**Date:** 2026-09-25
**Goal:** The Issues tile on the app rail shows the count of open issues belonging to the active workspace, not the whole store.
**Granularity:** medium

## Context

The Issues store is a single cross-workspace blob persisted at `~/.minnow/issues/state.json`; every card carries a `workspacePath` (`IssueCard.workspacePath`, `src/types.ts:885`). The Issues app itself scopes its default list to the active workspace via `collectIssues({ scope: 'current_workspace', workspacePath: getWorkspacePath(), hideDone: false })` (see `src/ui/issues-page.ts:645`), and the Home app does the same for its open-issue count (`src/ui/home-page.ts:670`).

The app-rail badge does not. `bindIssuesDockBadge()` in `src/os/app-rail.ts:300-352` calls `issuesStore.listIssues()` — the entire unfiltered store — and hands it to `computeIssuesDockBadge()` (`src/issues/dock-badge.ts`), which counts unreviewed triage items plus `awaiting_input` agent items (skipping closed statuses via a taxonomy callback). So a user with issues in several workspaces sees a badge that inflates with work that does not belong to the workspace open in front of them.

The fix is to scope the data source, not to change the counting rules: swap `listIssues()` for the store's canonical `collectIssues` workspace-scoped query. `hideDone: false` keeps closed issues in the input so the badge's own taxonomy-based `isClosed` callback remains the single closed-issue filter (preserving today's behavior while the taxonomy store is still loading).

Out of scope: `countOpenIssues()` (`src/state/issues-store.ts:2349`) intentionally uses `scope: 'all'` for the in-app summary row — do not touch it.

- **Build:**

## Notes for Build Agents
- Only the badge's **data source** changes. The counting rules in `computeIssuesDockBadge` (`src/issues/dock-badge.ts`) and its taxonomy-based closed-skip stay exactly as they are — pass `hideDone: false` to `collectIssues` so the badge remains the closed-issue authority.
- Workspace comparison is `normalizeWorkspacePath`-based **inside** `collectIssues` (`src/state/issues-store.ts:2316-2319`) — do not duplicate normalization at the call site.
- Keep the existing `isIssuesStoreLoaded()` guard and try/catch around the query; `collectIssues` calls `requireIssuesState()` and may throw when the store is unloaded.
- Do not touch `countOpenIssues()` — its `scope: 'all'` is deliberate for the Issues app summary row.
- The rail badge subscription (`subscribeIssuesChanges`) already re-syncs on any issue mutation; no event wiring changes are needed.
