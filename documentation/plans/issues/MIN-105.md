# MIN-105 — Tokens per second not calculated during reasoning / thinking

**Date:** 2026-10-01
**Goal:** The live metrics strip reports a tokens-per-second value while a reasoning model is thinking, before any prose has streamed.
**Granularity:** medium

## Context

**Issue:** MIN-105 (bug, priority medium). "Tokens per second is not calculated while the model is reasoning / thinking." Expected: the tok/s metric is calculated and reported during the reasoning/thinking phase.

**Symptom:** During a reasoning model's thinking phase, `#stripTPS` in the bottom metrics strip shows `—`. It only populates once prose starts streaming (or the round ends).

**Root cause (verified in code):**

1. Live stats are produced by `createStreamingStatsPublisher` → `buildLiveStreamMeta` → `buildLiveStreamStats` → `buildCurrentRoundUsage` (`src/chat/streaming-stats.ts`).
2. `buildCurrentRoundUsage` estimates the in-flight completion count as `estimateTokensFromText(partialText)` — **prose only** (`src/chat/streaming-stats.ts:44`). `partialThinkingLength` is passed into the snapshot by both call sites (`src/chat/run-turn-chat.ts:1143`, `src/api/chat.ts:909`) but is **not read** by `buildCurrentRoundUsage`.
3. During thinking, `partialText` (streamed prose) is empty, so the estimated `completion_tokens` is `0`. `decodeWindowCompletionTokens` (`src/api/chat.ts:424`) then returns `null`, and `buildClientStats` (`src/api/chat.ts:469`) produces no `tokens_per_second`. The strip shows `—`.
4. Reasoning that streams **does** decode inside the measured window: `run-turn-chat.ts:1568-1569` sets `liveStreamMeta.streamed_reasoning = true` on the first thinking event, and `decodeWindowCompletionTokens` includes the full completion count when `streamedReasoning === true` (`src/api/chat.ts:430`). So counting streamed reasoning in the live estimate is consistent with the existing accounting — only the estimate is missing it.

**Deliberate invariant to preserve:** hidden reasoning (a provider that bills reasoning tokens but never streams them) must stay out of tok/s. `decodeWindowCompletionTokens` excludes it (`src/api/chat.ts:431-436`) and the existing test `does not estimate completion from thinking length (provider reports it)` (`test/chat/streaming-stats.test.mts:69-79`) locks that in. The fix therefore gates the reasoning estimate on `streamMeta.streamed_reasoning === true`; hidden reasoning never produces thinking events, so `partialThinkingLength` stays `0` anyway.

**Out of scope:** the turn-end/round-end rate (`finalizeResponseMeta` / `reconcileCompletionStats`) — its hidden-reasoning behavior is intentional and unchanged; the per-message stats chip and the token ledger; provider-side timings (still authoritative when present).

## Wave Breakdown

### Wave 1 — Count streamed reasoning in the live estimate

#### Task W1-A: Add streamed reasoning tokens to `buildCurrentRoundUsage`

- **Build:**
  - In `src/chat/streaming-stats.ts`, change the import on line 8 to also bring in `charsPerTokenFor`:
    `import { charsPerTokenFor, estimateTokensFromText } from './prompts/token-estimate-core';`
  - Add an exported helper (place it just after `hasLiveCompletionUsage`, before `buildCurrentRoundUsage`):
    ```ts
    /**
     * Token estimate for reasoning text we only hold as a length. Mirrors
     * `estimateTokensFromText` for the prose class without materialising the string.
     */
    export function estimateReasoningTokens(length: number | undefined): number {
      if (!length || length <= 0) return 0;
      return Math.round(length / charsPerTokenFor('prose'));
    }
    ```
  - In `buildCurrentRoundUsage` (`src/chat/streaming-stats.ts:39-68`):
    - Destructure `partialThinkingLength` alongside the existing fields:
      `const { streamMeta, partialText, partialThinkingLength, priorStatsSegments } = input;`
    - Replace `const roundEstimate = estimateTokensFromText(partialText);` with:
      ```ts
      // Reasoning that streamed decodes inside the measured window, so its tokens
      // belong in the live estimate; hidden reasoning must stay out (see
      // decodeWindowCompletionTokens in src/api/chat.ts).
      const streamedReasoning = streamMeta.streamed_reasoning === true;
      const roundEstimate =
        estimateTokensFromText(partialText) +
        (streamedReasoning ? estimateReasoningTokens(partialThinkingLength) : 0);
      ```
    - Leave the rest of the function (provider-usage preference, `priorStatsSegments` hold) unchanged.
  - Expected diff: ~15 lines in one file. No other module changes.
- **Test:**

Assert `usage.completion_tokens === Math.round(400 / charsPerTokenFor('prose'))` and `usage.total_tokens === usage.completion_tokens`.

## Notes for Build Agents

- The single source of truth for the estimate is `buildCurrentRoundUsage` in `src/chat/streaming-stats.ts`. Both the run-turn live path (`src/chat/run-turn-chat.ts:1133-1150`) and the streaming fallback in `src/api/chat.ts:905-912` already pass `partialThinkingLength`; do not touch those call sites.
- Preserve the invariant: **hidden** reasoning (billed but never streamed) must not inflate tok/s. Gate on `streamMeta.streamed_reasoning === true`; the existing test at `test/chat/streaming-stats.test.mts:69-79` enforces this and must stay green.
- Provider `usage.completion_tokens` from `stream_meta` still wins whenever present (`hasLiveCompletionUsage` early return) — the reasoning estimate is only a live fallback.
- Use `charsPerTokenFor('prose')` rather than a hard-coded divisor, so a future recalibration of the shared estimator does not silently desync this path. `charsPerTokenFor` is already exported through `src/chat/prompts/token-estimate-core.ts`.
- Do not change `decodeWindowCompletionTokens` / `reconcileCompletionStats` in `src/api/chat.ts`; their reasoning handling is intentional and out of scope.
