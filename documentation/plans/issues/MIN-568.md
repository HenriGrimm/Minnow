# MIN-568 — Concurrent MTPLX model execution

## Goal and scope
Enable two distinct MTPLX chat models to remain resident and complete overlapping generations on a supported Apple Silicon Mac when their combined memory requirements fit the existing residency budget. Cover explicit My Models loads and pool-driven just-in-time loads, model-correct routing, cancellation, eject, crash isolation and resource-pressure handling.

Issue: MIN-568 (medium, todo). Execution: Build, sequentially in one chat. Granularity: medium. Planning date: 2026-10-20.

Assumption: the issue's “MTP LXM hardware” means the MTPLX runtime on Apple Silicon, not a distinct accelerator. Do not broaden this into concurrent mlx-lm model hosting, a new inference engine, retrieval-model concurrency, or same-model batching. No implementation or tests were run during planning.

## Decisions and constraints
- Retain one owned MTPLX process per chat model, separate ports, existing serve rows and the shared `mtplx-local` engine provider identity. Do not introduce per-serve provider records or a new persistent store.
- Preserve platform gating from `isMtplxSupported`: Darwin/arm64, Darwin release >=23 (macOS 14). Keep mlx-lm's single-model lifecycle unchanged.
- Existing support is partial, not absent: `startMtplxServe` deduplicates canonical model paths, picks ports and adopts matching external daemons; `admitLocalCompletion` selects the actual serve endpoint. Do not rewrite these paths without a failing regression.
- Confirmed blanket restriction: `bindRouterLibraryEntry` uses a global `enqueue` mutex and `otherLocalServesBusy` waits on every other active local serve before admitting an unloaded model. Replace this wait only for verified MTPLX execution; an `mtplx:` library id can explicitly select mlx-lm via saved launch preferences and must retain the old behavior.
- Keep serialized allocation/admission critical sections; concurrent execution does not require simultaneous weight loading. A ready model must remain usable while another eligible model loads. Do not simply delete every mutex.
- Capacity remains bounded by `resolveResidencyLimits`, `estimatePlanMemoryBytes` and `pickEvictions`. `admitServe` currently skips busy victims after its deadline and returns without proving capacity; close that gap before allowing router loads alongside busy residents. Never terminate native or Minnow-owned in-flight work merely to make room.
- External daemons are not owned: never kill or evict them. Available system memory and any observed external usage must not be counted twice; document conservative handling where usage is unknown.
- Upstream verification: Context7 `/youssofal/mtplx` documents `serve --model ... --port ...` and isolated cache/log paths, and describes one execution-owner thread per server. It does NOT establish that two chat-model processes work on every installed release. Verify the installed version with a native two-process smoke test before claiming hardware acceptance. Do not treat retrieval multi-residency or same-model batching as proof.
- No new upstream flags are required by this plan. Existing `buildMtplxServeLaunch` controls model, port and authentication. Preserve those restrictions.

## Implementation steps

### 1. Establish concurrent routing regressions and native feasibility
- [ ] Reproduce the MTPLX router wait deterministically and establish native multi-process feasibility.
- Changes: Extend `test/model-routers/library-serve.test.mjs` using its injected dependencies and bounded fake clock: model A has an active MTPLX generation, model B is unloaded, and B's resolver must be reached without waiting for A to end. Add a saved-engine mlx-lm control case. Extend `test/providers/local-completion-admission.test.mjs` with two distinct MTPLX serves and assert `admitLocalCompletion` returns the correct distinct base URLs regardless of provider default URL or load order. Use scratch `MINNOW_HOME` and restore all overrides.
- Verify: Run `node --test --test-force-exit test/model-routers/library-serve.test.mjs test/providers/local-completion-admission.test.mjs`. Confirm the new router case fails for the intended idle-wait reason, not a fixture error. On a macOS 14+ arm64 machine, record installed MTPLX version, two validated model paths, available unified memory and launch settings; launch the two models on separate loopback ports and issue overlapping streaming completions. Capture both health identities and first/last token timestamps. If the installed runtime blocks independent processes, stop implementation of the concurrency bypass and resolve the supported runtime/version requirement; do not invent a flag or silently substitute same-model concurrency.

### 2. Make residency admission fail closed under contention
- [ ] Admission permits a second model when it fits and refuses unsafe launch when capacity cannot be reclaimed.
- Changes: Update `admitServe` in `server/models/serve.js` to recompute live residency after eviction waits and require count and memory constraints to be satisfied before returning. On deadline exhaustion with busy/native-active victims, return a clear bounded capacity error rather than letting `startMtplxServe` spawn anyway. Reject an incoming estimate that alone exceeds the budget. Account for starting reservations and serialize the capacity-check/row-reservation operation so simultaneous MTPLX starts cannot both consume the same free capacity. Keep `mtplxStartQueue`'s useful allocation protection; do not hold a residency mutation lock throughout a full generation. Update `startMtplxServe` only as necessary to reserve/release capacity cleanly on launch failure. Preserve existing cap configuration rather than adding a settings surface.
- Verify: Run `node --test --test-force-exit test/models/admit-serve.test.mjs test/models/serve-admission-busy.test.mjs test/models/mtplx.test.mjs`. Extend tests to assert: two fitting MTPLX plans need no eviction; busy victims remain running but exhausted admission rejects; an oversized plan never invokes process creation; idle eviction frees enough memory; failed starts release reservations; competing starts cannot oversubscribe. Update the existing busy-victim test's success expectation to the explicit refusal while retaining its no-stop assertions.

### 3. Allow eligible MTPLX router loads alongside active models
- [ ] Pool-driven model B starts while model A is generating when safe capacity exists.
- Changes: Add an exported `resolveLibraryTargetRuntime` helper in `server/models/library-binding.js` that uses the same cached-target and saved-engine logic as `resolveCachedTarget`; expose it through the existing router dependency-injection pattern. In `bindRouterLibraryEntry` / `otherLocalServesBusy`, bypass the blanket other-model idle wait only when this resolver establishes that the actual target is MTPLX. Leave authoritative capacity checking to step 2. Move already-running serve reuse outside the global load queue, rechecking state inside the queued load path to avoid duplicate starts. Preserve the existing wait behavior for mlx-lm, including saved mlx-lm fallback for an `mtplx:` entry, and other runtime paths. Keep phase cleanup and abort/error propagation correct.
- Verify: Run `node --test --test-force-exit test/model-routers/library-serve.test.mjs test/models/library-binding.test.mjs test/models/mtplx.test.mjs`. Assert the step-1 MTPLX regression passes, fitting B resolves before A ends, already-running A is not blocked by B's queued load, duplicate B requests reuse one start, mlx-lm fallback still waits, failed capacity admission starts no process, and cancellation clears waiting/loading phase state without stopping unrelated models.

### 4. Prove per-serve identity and lifecycle isolation
- [ ] Loading, stopping or failing one MTPLX model does not redirect or terminate another.
- Changes: Extend `test/models/mtplx.test.mjs`, `test/models/mtplx-crash.test.mjs` and `test/providers/local-completion-admission.test.mjs` with two-process fixtures. Exercise distinct ports, same-path duplicate loads, same/different external-daemon adoption, reverse completion order, one-model cancellation, eject, health failure, crash and survivor routing. Change `findLiveServeForRuntime`, `remapFromServe`, `admitLocalCompletion` or `startMtplxServe` only where those tests demonstrate incorrect identity/cleanup. For colliding configured model labels, use an unambiguous internal identity such as canonical model path through binding and lookup, while keeping the upstream request's advertised model id valid; add a regression instead of relying on newest-row selection. Do not disable a shared provider while a sibling remains live. Audit per-row authentication when adopted and owned endpoints differ; do not route one endpoint's credentials to another.
- Verify: Run `node --test --test-force-exit test/models/mtplx.test.mjs test/models/mtplx-crash.test.mjs test/models/library-binding.test.mjs test/providers/local-completion-admission.test.mjs`. Assert endpoint identity rather than merely successful responses, exactly one owned process for repeated same-model loads, survivor completion success after eject/crash of its sibling, and no process-stop call for an adopted daemon. Authentication fixtures must use dummy secrets and never print credentials.

### 5. Perform native acceptance and document the shipped contract
- [ ] Real hardware demonstrates overlapping model execution, with automated regressions and limitations recorded.
- Changes: Update `documentation/context.md` with the implemented MTPLX multi-model routing/admission contract, actual supported runtime version verified in step 1, memory limits, and unchanged mlx-lm behavior. Keep documentation claims conditional on measured native results. No throughput guarantee: overlapping streams are the contract, not a speedup.
- Verify: On the supported Mac, use Models to load A and B and select them in separate chats. Start a sufficiently long generation on A, then send B while A is still producing tokens. Record both serve ids, ports, canonical model paths, runtime version, memory settings and timestamps showing B emits tokens before A ends. Repeat with B initially unloaded through a model pool, with both estimates fitting capacity. Cancel/eject B and verify A completes; repeat load/retry after a B failure. Force a low-capacity configuration and verify clear bounded refusal without terminating A or spawning an over-budget process. Run `npx tsc --noEmit`, `npm run test:check-coverage`, `npm test`, and `npm run build`; distinguish any pre-existing unrelated suite failures from new failures. Native acceptance is blocked, not passed, if no suitable Mac/two-model memory budget is available.

## Acceptance checklist
- [ ] Two distinct MTPLX chat models on a supported Mac produce overlapping streaming output with model-correct responses and distinct endpoints.
- [ ] A fitting pool-triggered cold load does not wait for an unrelated active model's generation to end.
- [ ] Same-model requests do not spawn duplicate processes; explicit model-label collisions cannot silently misroute requests.
- [ ] Admission honors memory/count limits, includes starting allocations and fails safely when busy residents cannot be reclaimed.
- [ ] Cancel, eject or crash of B leaves A usable; external daemons are never killed by Minnow.
- [ ] Saved mlx-lm fallback and non-MTPLX lifecycle behavior remain compatible.
- [ ] Focused tests pass; typecheck, coverage discovery, full-suite and build results are recorded without hiding baseline failures.
- [ ] Native evidence includes runtime version and overlapping token timestamps, not just two running rows or HTTP 200 responses.

## Risks and open questions
- Terminology is inferred: MTPLX on Apple Silicon is the verified codebase match for “MTP LXM”; a different intended runtime requires rescoping.
- Runtime-level multi-process compatibility is not proven by current mocks or upstream request-concurrency documentation. The native feasibility gate must resolve this before bypassing router waits.
- MTPLX's per-process default memory policy may assume a large share of total RAM; aggregate estimates and explicit per-model limits must be checked against actual health memory plans. Do not claim unlimited model residency.
- Shared provider metadata/authentication and user-configured duplicate labels can hide endpoint-specific errors; step 4 must verify actual request destinations and credential boundaries.
- Changing `admitServe` from silent continuation to explicit refusal affects its llama.cpp callers too; retain no-interruption guarantees and add compatibility regressions.
- Brain search was not available through permitted MCP discovery. Injected historical notes were reviewed, but current source files are the authority.
