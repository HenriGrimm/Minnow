# Chat execution production validation — 2026-11-07

This report supersedes the historical partial/native-blocked statements in the earlier implementation reports. Supported ordinary roots use the existing canonical server runtime by default. The Codex native experiment remains default-off and restricted to the verified Windows Codex 0.166.0 / gpt-5.5 candidate. This local validation does not certify macOS/Linux native enforcement, signed installers, unsupported historical chat migration, or paid-provider behavior.

## Review and corrections

- Kept the shared runner, canonical transcript, fenced admission and uncertain-effect recovery. Added synchronous native authority revocation before provider capabilities, MCP, plugin/connection, work-agent, prompt and skill-pack authority writes. External profile events also invalidate authority when a rapid revoke/regrant leaves identical final bytes. Interrupted native work requires recovery rather than silently acquiring new permissions.
- Removed unnecessary checkpoint work without reusing stale workspace state. Ordinary read-only turns take no captures; the first mutating tool's fresh pre-image also serves as the baseline under the same uninterrupted checkout lock. Later tools always take fresh pre/post captures. Native execution still awaits its eager baseline. Git metadata reads and independent index/anchor work overlap; the real index remains byte-identical.
- Fixed the fresh-profile starter chat not being included in its first scalar save, lost tool-argument activity after a chat remount, and invisible canonical preparation failures. Failure text is bounded/redacted and remains visible after reload/acknowledgement without modifying transcript history.
- Fixed first-send promotion of a new root with an inherited bare model ID: its existing catalog/default provider binding is resolved before the durable revision-checked save. Fresh roots can use their matching remembered pair before the catalog loads; historical roots do not acquire this fallback. Both real HTTP regressions verify the complete selection is stored before promotion and command admission.
- Extended bounded Windows atomic-rename retries for transient scanner/sharing locks while retaining atomic replacement. Removed test teardown races and machine-dependent fixtures. Seven HTTP/fs/DOM suites use natural Node exit to avoid a reproduced Node 24 Windows libuv force-exit abort; assertions and test deadlines remain enabled. Vite ignores temporary `.minnow` output to avoid executable watcher locks.
- Fixed the Windows packaging cleanup guard hanging in `(Get-Process).Path`: CIM now supplies executable paths and the subprocess has a 15-second deadline. Failure still prevents cleanup. The real copied-executable/sibling-preservation regression passes.
- Encrypted secret replacement shares the bounded atomic-rename helper after real MCP secret writes hit Windows sharing locks. The encrypted candidate is verified before replacement; tests prove the previous secret remains intact during retries and the pending file contains an encrypted envelope.
- Provider profiles/capabilities use the same bounded replacement helper. A real board-testing HTTP regression injects transient provider locks; registration failure also closes the newly listening fake-model host. Legacy app metadata reads now share the existing per-app write queue, preventing polling from starving atomic publication. The gated-reader regression proves readers observe the committed metadata rather than opening the old file during replacement.
- Fixed a local command cancellation race: killing a still-starting worker could miss its newly spawned command. Workers now acknowledge readiness before launch and accept cooperative cancellation; cancellation waits for command termination, worker close and final bookkeeping before releasing the checkout. A bounded process-tree fallback remains. The actual packaged Electron API verifies immediate cancellation, cancellation after the command demonstrably starts, process termination and subsequent checkout reuse.
- One-shot CLI cleanup now uses the same bounded transient-sharing-lock removal retries as persistent CLI sessions. The full suite exposed a private generation directory remaining after a failed invocation; the affected suite passed all 24 cases, then passed three more consecutive runs (72 cases).

## Checkpoint latency

[Raw paired results](chat-performance-checkpoint-results.json) were measured with the real coordinator, SQLite journal and Git, 200 tracked files, distinct staged/unstaged changes and an untracked file. One warmup and five alternating paired samples per workload ran on Windows x64, Node 24.19.0, 32 logical CPUs. Concurrent regression work was active. These are synthetic coordinator measurements, not inference or end-to-end conversation latency; five observations do not establish a release p95.

| Scripted writes | Captures before → after | Coordinator p50 before → after |
| ---: | ---: | ---: |
| 0 | 1 → 0 | 648.39 → 1.68 ms |
| 1 | 3 → 2 | 1676.54 → 801.39 ms |
| 5 | 11 → 10 | 5737.96 → 3886.67 ms |

The harness asserts journal boundaries, preservation of staged/unstaged/untracked state, and byte-identical user index. Separate regression cases verify intervening external edits are captured, HEAD changes fail closed, Stop/pre-capture failure prevent effects, and post-capture uncertainty blocks further writes. There is still real Git latency on every mutating boundary; eliminating those remaining captures would require a different proven safety mechanism.

Reproduce with `node scripts/benchmark-chat-checkpoints.mjs --baseline-file <original-git-ops.js> --samples 5 --files 200 --output <results.json>`. The original file is `server/git/git-ops.js` from `ca398a8b7cba5171a1d4154d20fed061549dadd4`; the saved benchmark input matches that file after CRLF normalization. Its exact SHA-256 is recorded in the raw results. The original local copy was retained only as ignored benchmark input, not a production dependency.

The [original Minnow checkout measurement](chat-performance-reference-checkpoint-results.json) also verified byte-identical real index and unchanged HEAD across paired captures: 6,259 tracked files, one warmup, three measured samples per implementation. Capture p50 was 764.7 ms before and 627.3 ms after under active regression load. This is the current working checkout, not a reconstruction of the earlier 1.8-second planning observation, and remains a component measurement.

- Built the SPA and headless runner. Windows unpacked app launched with a separate profile. - [Final packaged evidence](chat-performance-packaged-results.json) records the actual ASAR digest. In that artifact, a new root sent successfully, its saved reply remained available after a whole-app restart, and a second turn completed. SQLite confirmed exactly two settled commands, two user/assistant pairs and zero checkpoint rows for those read-only turns. The authenticated live PTY script passed all seven assertions, including WebSocket output and session deletion. Their bounded timing summaries are retained in the packaged evidence, separating workspace/preparation, request/first prose, transcript durability and settlement. The evidence also verifies all 24 changed server JavaScript files against the archive byte-for-byte.
- [Renderer measurements](chat-performance-renderer-results.json): the real source conversation painter in an isolated packaged Electron window, four simultaneous 100-tick streams with Markdown/code blocks, 400 frame samples. First text reached DOM in 16.9–18.6 ms; received-to-next-frame p95 was 15.4 ms. Six synthetic keyboard-input-to-frame samples were 0.2–10.8 ms. No long tasks or API calls were recorded. This is one synthetic renderer run, not a hardware compositor or broad interaction p95 certification. Shared-preview timings were discarded because its scheduling suspended animation frames between automation actions.

Those fixtures now await teardown or isolate the unrelated viewer refresh; no assertion was removed. The individually corrected suites passed 46 cases (12 file operations, eight code-map review, 16 composer/issues/default-model and ten terminal cwd).
