# Remote Devices Overhaul

**Date:** 2026-10-18
**Goal:** A phone connects to Minnow in two taps with nothing to install, stays connected through host restarts, network changes and Home Screen installs, and works away from home through a Tailscale node built into Minnow.
**Granularity:** medium

## Context

### What is broken today

The LAN companion (MIN-393) serves `http://<lan-ip>:<port>` and keeps a `minnow_device_*` token in `localStorage` plus a script-written cookie ([`src/api/session-token.ts`](../../src/api/session-token.ts)). Users must re-pair from Settings constantly, the Home Screen app asks for a new code, and pairings vanish after restarts. Root causes found in this checkout:

1. **Origin drift.** Browser storage is per origin (scheme + host + port). DHCP changes the IP; `npm start` uses Vite `strictPort: false` ([`server.js`](../../server.js)) and Electron falls back to an ephemeral port when 9473 is busy ([`electron/loopback-listen.ts`](../../electron/loopback-listen.ts) `listenOnPreferredNetwork`). A new origin is a fresh, empty storage jar, and an installed Home Screen app is pinned to the dead one.
2. **Stale host allowlist.** `getOwnLanHostnames()` in [`server/network/access.js`](../../server/network/access.js) caches interface addresses forever, so after a Wi-Fi/IP change every `/api/*` call returns `403 Forbidden host` until the host restarts — the phone shows "reconnecting" indefinitely.
3. **Safari erases script-writable storage.** ITP deletes `localStorage` and `document.cookie` cookies after seven days of Safari use without interaction; script cookies are also capped at seven days. Only server-set cookies escape this.
4. **Home Screen isolation.** iOS gives Home Screen apps separate cookies and storage. The current handoff swaps `<link rel="manifest">` after boot and carries the raw token in a `#device=` fragment of `start_url` ([`server/auth/routes.js`](../../server/auth/routes.js) `/api/auth/manifest`); when iOS ignores either, the user needs a code.
5. **Every reconnect creates a new device.** [`server/auth/device-store.js`](../../server/auth/device-store.js) stores one token per device; re-pairing appends a duplicate, and each pairing requires typing a name and racing a 5-minute code.
6. **Plain HTTP is not a secure context.** No service worker, unreliable install, no camera/mic, no `crypto.subtle`, no web push.
7. **LAN mode needs a restart** and rebinds the whole server to `0.0.0.0`, including the desktop listener and the isolated preview host ([`server/preview/isolated-host.js`](../../server/preview/isolated-host.js)).

### What users will see after this plan

**Home network (no account):** Mac: Settings → Devices → **Connect a phone** (first time only: choose "On my Wi-Fi", which starts the listener live). Phone: scan QR with the Camera → **Connect**. Done — two actions on each side.

**Anywhere (one-time, built in):** Settings → Devices → **Make it work anywhere** → browser opens the Tailscale sign-in (Google, Apple, Microsoft or GitHub; free personal plan) → if the tailnet needs it, one **Enable** page for HTTPS/Funnel → card shows **Ready** with `https://minnow-<host>.<tailnet>.ts.net`. From then on the QR uses that address; the phone still installs nothing.

**Home Screen app:** after connecting, the phone shows "Add Minnow to your Home Screen" (Share → Add to Home Screen on iOS, an Install button on Android). The installed app signs itself in through a handoff ticket in its start address. If iOS drops it, the app shows **Scan QR** (camera, HTTPS only) or **Request access** → a 4-digit number → the user taps **Approve** on the Mac.

**Trouble states:** "Can't reach <host>" banner with a cause-specific hint (same Wi-Fi? Mac asleep? internet?) that retries forever and never discards the login; "Disconnected" only after a real revoke, with **Request access again**.

### Constraints and decisions

- **Zero install on the phone.** Achieved with Tailscale Funnel: the phone talks plain HTTPS to a public `ts.net` name; TLS terminates in Minnow's own tsnet node. Funnel ports are 443/8443/10000 and bandwidth is capped by Tailscale (fine for chat streaming).
- **Zero install on the host.** Tailscale runs in-process as a bundled Go sidecar built with `tailscale.com/tsnet` (BSD-3-Clause). It never touches a system Tailscale install and needs no firewall rule (outbound only).
- **Funnel is internet-exposed.** `ts.net` names appear in Certificate Transparency logs. Device pairing is therefore the only gate, so on Funnel ingress: no 6-digit code entry, access requests only while the host has a pairing window open, global unauthenticated rate limits, and the host credential is never accepted.
- **The desktop listener is always loopback.** Remote traffic arrives on separate listeners tagged by ingress (`loopback`, `lan`, `tailnet`, `funnel`). Tagging is by accepting listener, never by peer address — the sidecar proxies from `127.0.0.1`.
- **One credential per origin, one device record per phone.** A device holds several credentials (browser, Home Screen app, other origin). Approve and handoff attach a credential to an existing device instead of creating a new one.
- **Defaults chosen in planning (revisit later):** no auto-approve for same-tailnet users in v1; an already-paired phone cannot approve other devices; Windows/Linux home-network QR uses the IP (macOS uses its Bonjour `.local` name); web push notifications are a follow-up that this plan unblocks.

### Wave 2 — Auth model and listeners

#### Task W2-A: HttpOnly device cookie and same-origin enforcement
- **Build:** Create `server/auth/cookie.js`: `DEVICE_COOKIE = 'minnow_device'`; `setDeviceCookie(res, token, { secure })` writes `HttpOnly; Path=/; SameSite=Lax; Max-Age=34560000` (400 days) and `Secure` when the ingress is `tailnet`/`funnel`; `clearDeviceCookie(res, { secure })`; `readDeviceCookie(req)` parses the `Cookie` header. In `server/runtime/auth-middleware.js` resolve credentials in order header `X-Minnow-Token` → `?token=` → device cookie, remembering `req.minnowAuthSource`. For cookie-sourced auth enforce same-origin: non-GET/HEAD requires `Origin` equal to `${scheme}://${host}` (scheme `https` for `tailnet`/`funnel`, else `http`); GET requires `Sec-Fetch-Site` absent, `same-origin` or `none`; failures return `403 { error: 'Cross-origin request' }`. This matters because cookies are shared across ports on the same IP (e.g. LM Studio on :1234). Rolling refresh: if the device was last refreshed more than 24 h ago, re-send `setDeviceCookie` on the response. On a confirmed unknown/revoked cookie credential send `clearDeviceCookie` with the existing `401` + `X-Minnow-Auth: required`. After auth call `touchDevice`. Apply the same cookie read + `Origin` check inside `checkUpgradeAccess` (W1-A) for WebSocket upgrades. Add `POST /api/auth/adopt` handling to the middleware's allow path is not needed — adopt is an authenticated call (W2-B route) that simply converts a header-sent legacy token into the cookie.
- **Test:** New `test/remote/cookie-auth.test.mjs`: a GET with only the cookie on a `lan` ingress returns `200`; the same with `Sec-Fetch-Site: cross-site` returns `403`; a POST with cookie and `Origin: http://192.168.1.5:1234` returns `403`, with matching `Origin` returns `200`; a revoked cookie returns `401` and a `Set-Cookie` that clears `minnow_device`; a WebSocket upgrade with cookie and mismatched `Origin` is refused; a request 25 h after the last refresh carries a fresh `Set-Cookie`. `npm run test:remote` and `node test/run-all.mjs --suite security` pass.
- **Accept:** A paired phone authenticates every API call, EventSource and WebSocket through the cookie alone, and a page on another port of the same host cannot use it.

## Notes for Build Agents
- Read `documentation/context.md` (auth, LAN companion, startup recovery) before touching `server/runtime/*` or `src/companion/*`. Remove superseded context paragraphs only in W5-A.
- **Never decide "is this the host" from the peer address.** The sidecar connects from `127.0.0.1`. Use `getRequestIngress(req)`; only `loopback` ingress may present the host token or receive it in HTML.
- Device credentials must never appear in URLs, logs, manifests, or `localStorage` after W3-A. Tickets in URLs are single-use or device-bound and short-lived; QR tickets ride the fragment.
- Keep `/api/auth/session` the only endpoint whose `401` + `X-Minnow-Auth: required` means "revoked". Provider `401`s and `503` storage errors never disconnect a phone.
- The desktop listener stays `127.0.0.1:9473` and must not drift (`strictPort: true`); remote listeners fail loudly instead of switching ports.
- iOS relaunches the Home Screen app at `start_url` every time; a consumed `?handoff=` with a valid cookie must redirect silently.
- UI copy follows the product voice: sentence case, verb-first buttons, no "please", no exclamation marks. CSS uses `--mn-*` tokens only (`DESIGN.md`).
- `~/.minnow/tailnet/` holds the node identity; it is never backed up and is deleted by Sign out.
- The tsnet API evolves; pin the `tailscale.com` version in `go.mod` and confirm `ListenFunnel`, `QueryFeature`, and `WhoIs` signatures against that version before writing the sidecar.
- Follow-ups unblocked by this plan (out of scope): web push for agent-finished and approval-needed events on the HTTPS origin; auto-approve for same-tailnet users; per-device scopes such as no terminal over Funnel.

## Implementation notes

Built on branch `feat/remote-devices`. Where the build differs from the tasks above:

- **Install manifest is server-side.** Pages served to a signed-in device already point `<link rel="manifest">` at a ticketed manifest (`addDeviceManifestToHtml`), so there is no client `configureInstallManifest()`; Safari reads the right manifest before any script runs.
- **Access requests surface only in the global approval card** (top-right, under the menu bar, in any app) rather than also inline in Settings, so a request never shows two prompts.
- **`general.network` stays** as the agent-settable "Home network access" field (dangerous, confirmation required); writing it now starts or stops the listener live through `setLanEnabled`.
- **The desktop dev port still falls back** to the next free port (`strictPort: false`): phones no longer use it. The phone-facing home-network port is the one that never drifts.
- **The isolated preview host** keeps binding all interfaces when home-network access is saved on, decided at boot, so wide tablets can still open previews.
- **Layered dialogs no longer dismiss Settings.** Live testing showed the shell overlay closed Settings on any pointer-down outside `#settingsView`, including the app's own confirm dialog. Layers marked `data-above-shell-overlay` (app dialogs, the Connect sheet, approval cards) are exempt.
- **Go helper** pins `tailscale.com` v1.104.1 (Go 1.27). `go vet`/`go test` pass, and the real binary reaches the Tailscale sign-in step; completing sign-in and Funnel approval needs a Tailscale account and is part of the manual checklist.
- **No `jsqr`.** The in-app scanner uses the browser's `BarcodeDetector` (Chromium on Android) and is hidden elsewhere; Request access covers the same case. This keeps the build under the total-assets budget (jsQR alone was 130 KB).
