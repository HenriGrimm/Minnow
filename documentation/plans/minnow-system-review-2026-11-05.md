## Where to start

1. **Isolate the desktop preview and enforce the agent's required shell sandbox.** A preview on a separate local origin used a fixture host credential. A background-command tool ran despite its required sandbox being disabled. Ship these as two independent fixes and verify a working local preview and a correctly sandboxed background build. See P1 and F8.
2. **Protect the user's project from ordinary Code actions.** Refuse recursive deletion of the project root, keep dirty drafts when switching workspaces, give New File and Move explicit collision behavior, and preserve the Git index during agent Undo. See F1–F4 and F9.
3. **Keep recoverable data recoverable.** Publish the first encryption key exactly once, make an interrupted restore restartable, and route recognized SQLite corruption through the existing verified-snapshot recovery.
4. **Make the parent agent's view match what happened.** Preserve explicit blocked verdicts, enforce cancellation ownership, and keep restart records independent of clipped display text. Each has a small deterministic regression case.

The shared runner, tool server and stores are worth keeping. Most failures below occur *between* two working components. For example, checkout containment is correct for a read of the root directory. The identical target is destructive when the next operation recursively deletes it. Likewise, the file contents restored by Git Undo can look right while the next commit includes edits the user never staged.

## Evidence and scope

Three subagents divided agent execution, workspace/Code, and data/apps. The coordinating review traced desktop, ingress, identity, config, native/build boundaries and selected findings across those areas. The Git inventory covered 6,191 tracked paths. Of 5,219 matching source, script, style or markup extensions, 3,243 were outside `test/`. This includes generated or vendored material. We reviewed sections through entry points, their downstream effects and representative tests. Those counts describe the inventory, not files inspected line by line. Runtime examples used disposable workspaces, profiles, fake secrets and local services.

- **Reproduced** means the noted effect was observed. Entries distinguish real Git, files, SQLite, HTTP or Electron from controlled I/O interleavings, fixture processes, mocked transport and checks stopped before a destructive call.
- **Traced** means both sides of a contract were located in current source. A runtime or platform gate is still needed.
- Priority reflects potential harm, exposure and recovery cost. These fixtures establish that a failure is possible. They do not measure how often it occurs in real chats.

Three changes to engineering practice follow directly from these cases.

- **Put the decisive check beside the effect.** Give create, overwrite, move and recursive delete their own semantics at the filesystem boundary. Share canonicalization where it already works. Keep the UI responsible for explaining choices. This also applies to workspace ownership at a mobile mutation, agent cancellation and required shell containment.
- **Separate display data from recovery data.** Maintain capped, readable transcripts. Where code replays a tool call, restores the Git index or resumes a swap, give it a record that can represent the exact state it needs. Add versioning and compatibility at that boundary instead of replacing every store.
- **Test two actors or two lifetimes.** Concurrent first use, old process exits, revoked sockets, a second window and the first boot after interruption account for many of these failures. Add one narrowly targeted adversarial case and one ordinary successful case beside each fix. Use actual files, SQLite, Git, Electron or the proxy wherever a mock would bypass the behavior under test.

The existing [agent reliability review](agent-reliability-review-2026-11-05.md) covers the previous changes and their regression results. Findings F6, A3 and A4 identify conditions beyond its sequential text edits, normal restart receipts and individual image associations. Reuse those fixtures and add concurrency, an oversized argument and compaction respectively.

Git history places several decisive lines well before this review. The preview guest's web-security setting and recursive directory removal are present at `8e69702975` (May). The Undo restore path is present at `417b15e9f9` (July), the explicit background-shell override at `5bcf4d620f` (August), and the Electron workspace retarget at `c26ebed991` (September). The transcript clipping and image-adjacency rules predate the latest replay changes (`38888e24e4` and `40292300e1`). These are line-history checks. The fixtures above show which combinations still fail on today's working tree.

Before shipping any one fix, capture its failing case and a passing ordinary-use case on the current revision. Run both through the public entry point after the change, plus the owning suite and the usual type, build, platform and performance gates. Compare any remaining failures to the same starting revision. Keep storage migrations, public contract changes and routine guards in separate pull requests so that a rollback has a clear scope.
