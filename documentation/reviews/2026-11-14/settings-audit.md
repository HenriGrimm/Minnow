# Minnow Settings audit and improvement backlog

November 14, 2026 · Current working tree at `c3097383d`

The first fixes should make approval boundaries accurate, preserve working settings when a save fails, and get users from search to the setting they meant to change. The most important permission finding is that **Allow in this thread** can persist a global shell fallback when the sandbox is unavailable.

## Reviewer perspectives

- **Maya, novice student developer.** Looked for a first working chat model, recognizable editor and appearance settings, and plain-language permission and backup boundaries. She found that familiar terms can lead to the wrong surface and that provider connectivity alone gives little guidance on getting a usable model.
- **Priya, mid-level full-stack developer.** Changed editor AI, switched between repository and global instructions, and checked notifications. Fault-injected fixtures showed lost edit context and disagreement between displayed or cached settings and server state.
- **Sam, senior platform engineer.** Reviewed sandbox fallback, phone connectivity, backup contents, and extension trust and imports. The main issues were defaults and state changes whose scope was unclear at the point of approval.
- **Impeccable audit and critique.** A fourth reviewer independently inspected the Settings layout and controls, exercised navigation at desktop and phone widths, and ran axe and Impeccable's detector. Search focus, phone drill-down, and the expanded navigation were the strongest shared-interface findings.

These are simulated user perspectives. The browser pass used a temporary Windows dev server and synthetic Sandbox project. Fixture checks exercised the current search and permission code and rendered individual settings with simulated responses. Findings below identify where evidence came from. Real provider accounts, physical phones, packaged Electron, and restore operations were outside the verification scope.
