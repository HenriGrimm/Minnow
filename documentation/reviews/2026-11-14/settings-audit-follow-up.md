# Minnow Settings audit and prioritized improvements

November 14, 2026 · Working tree at `c3097383d`

Start with permission state, cloud provider validation, and archive selection. These flows can claim that a setting or selection is effective when the underlying state differs. Next, fix the shared search and navigation so people can reach controls without already knowing where Minnow puts them.

## Independent reviews

| Reviewer | Tasks | Main finding |
| --- | --- | --- |
| Early-career designer learning to code | Run a first chat, understand approvals, change appearance | A failed cloud connection can be shown as connected. A failed permission read looks like a confirmed setting. |
| Full-stack developer moving from a cloud IDE | Set up the editor, terminal, models, and developer tools | Search misses controls by their visible names. Editor can report a provider different from the one its request will use. |
| Platform engineer running local providers | Restore a backup, pair a phone, troubleshoot providers and services | An earlier archive inspection can replace a later selection. Devices and Diagnostics can show stale or unjustified status. |
| Impeccable reviewer | Review interaction, accessibility, responsive layout, theming, and visual design | Search and phone navigation lose keyboard focus. The desktop rail exposes 32 destinations before users have chosen a task. |

The three personas are simulated reviews. Verification used a temporary Windows Minnow home and Chromium, the application’s search index and ranker, isolated DOM fixtures with simulated responses, and source inspection. Native packaged Electron, physical pairing, live credentials, and applying a restore were outside the test scope. Provider rows changed in the working tree during the review. The final source still showed the legacy Active badge and the empty-catalog status. This follow-up sits alongside the [earlier Settings audit](settings-audit.md).

## Impeccable audit and critique

The reviewer scored technical health **13/20** and design health **25/40**. The restrained palette, familiar settings rail, clear selection, and grouped control rows fit the workspace. The largest design costs were navigation density, mismatched terminology, and feedback that arrives too late or reports the wrong state.

The whole-shell Impeccable CLI scan flagged one type hierarchy warning. The visual detector ran on Startup, Editor, and Access in the isolated browser. Its measurable findings included long prose lines in Editor and Access. The reviewer treated accent-color and clipping flags as advisory after checking the accent’s role and clicking a sampled search result. The temporary detector overlay was available only in the isolated browser.

## P1 · Fix permissions, provider setup, and recovery

1. **Keep shell approvals within the scope the prompt offers.** The renderer writes a global fallback when a sandbox exception is granted for the chat. Use the shared chat grant and show the sandbox state and any existing global fallback in Access. **Accept when** a chat grant leaves the global preference unchanged, a different chat still follows its own policy, and Require continues to block fallback. Match Auto and Full access help to the shared policy and its protected-path rules. Source-confirmed. [Approval handler](../../../src/tools/permission-gate.ts#L238) · [Access explanations](../../../src/ui/settings-filesystem.ts#L18) · [Shared policy](../../../src/lib/permissions.mjs)
2. **Show permission status accurately and protect normal keyboard navigation.** After a simulated 503 for permission metadata, Settings showed Manual selected while the composer still announced Auto. Shift+Tab from the composer opened a Full access confirmation and Cancel returned to the same textbox. Report an unavailable reading with Retry, identify any last confirmed value, and keep authorization fail-closed. Let Shift+Tab move focus backwards and use an explicit action to open the permission menu. Point Startup’s **Agent permissions** at the same selector. **Accept when** a failed refresh displays an error, a successful retry reconciles Settings and the composer, and reverse Tab works before and after using the menu. Fixture and source evidence. 3. **Validate a provider before saving it and guide users to a usable chat model.** In a DOM fixture, **Test and save** saved the cloud provider and credential before an auth failure. Reselecting the failed provider then showed Connected and enabled Continue. Use the existing draft connection check, preserve working credentials on invalid replacements, and distinguish saved connection, successful test, and models available. Use guided setup as the primary Startup action when no usable chat model exists. **Accept when** auth failures, unreachable servers, and successful connections with zero models each have a distinct status and next action. Changing presets must preserve the result of the check. A usable catalog leads to selecting a chat model. 4. **Keep restore preview tied to the selected archive.** In fixtures, a slow preview for archive A replaced B after B was selected. A failed typed archive path also triggered repeated inspections without further action. Track the current inspection, render failure in place, and give the confirmation the selected archive identity. **Accept when** delayed success or failure for A cannot replace B or become the submitted path, a failed typed path issues one inspection per explicit attempt, and Back restores focus to the initiating row or path field. [Archive selection and preview](../../../src/ui/backup-restore-panel.ts#L180)

An active chat with a different remembered default also produced a mismatch between the displayed and requested model. Check save responses, show pending/error with Retry, keep focus through refresh, and commit a model pin after explicit model selection. Derive the displayed effective model and readiness from the request resolver. Explain that Editor assistance applies to inline suggestions and Quick Edit. **Accept when** 500s preserve the prior saved value and draft, rapid edits settle on the last acknowledged change, and the displayed local or cloud binding agrees with requests for active-chat, default-only, pinned, and unavailable cases. Present a choice of Tailscale-only or public reachability with Minnow pairing before enablement. Show each connection type and phone requirements during pairing. Restore the local and Anywhere actions after failure and display an actionable inline error. **Accept when** the chosen reachability matches the first enable request, each connection path can retry after a failed request, a successful empty response shows “No devices yet,” and users can choose LAN for the QR when both targets are available. ## P1 · Make Settings searchable and keyboard accessible

7. **Index user tasks and give each result an exact destination.** `Default shell`, `word wrap`, and `tab size` returned zero matches in the real ranker. `default model` selected the Autopilot planner in the browser. Five Editor groups share an anchor, and a Models field hit opens the page without carrying its field key. Index visible control names and everyday terms, give fields unique anchors, and carry the destination into Models and Brain. Distinguish choosing a chat model, connecting a provider, setting up a local model, and assigning a model to an agent task. **Accept when** exact names and synonyms reach the intended control on the first result. Use `Default shell`, `autocomplete`, `turn on dark mode`, `default chat model`, `download local model`, `sub-agent model`, `goal evaluator`, `revoke phone`, `scheduled snapshots`, and `add MCP server` as regression queries. [Search index](../../../src/ui/settings-search-index.ts#L229) · [Editor field groups](../../../src/ui/editor-fundamentals-settings.ts#L25) · [Destination resolver](../../../src/ui/settings-search-navigate.ts#L327)
8. **Move focus with the destination and restore it on Back.** Selecting **Permissions** by Enter opened Access but left focus in Search. Tab went to General in the rail. Escape blurred the input, and axe flagged an empty search listbox. Opening Appearance at 390 px moved focus to the body. Use a single Tab stop for the combobox, announce empty results in a separate status, and focus the destination once its load completes. On phone Back, restore the originating row or Search for a direct link. **Accept when** Arrow keys, Enter, Escape, Tab, and Back work with a logical focus order at 1280 and 390 px, an empty result passes the axe rule, and a slower previous navigation cannot steal focus. Load each destination once, including search-triggered lazy sections. Browser, axe, and source evidence. ## Verification for the first implementation pass

Exercise the release-facing flows in this order. Use delayed responses and synthetic providers and archives for failure cases.

1. From Code, open the permission menu by keyboard, retry a failed level read, and verify a chat-scoped grant survives only within its intended chat.
2. From Startup, try an invalid cloud credential, switch presets, and complete setup with a populated test catalog. Confirm the prior working connection survives a rejected replacement.
3. In Backups, select A then B with out-of-order previews, enter an invalid path, and leave and reopen Settings while a backup job runs.
4. Use keyboard-only Settings search for the queries above at desktop and phone widths. Check that result activation loads the correct field once, Escape returns to input, and Back restores the initiating control. Repeat at 320 CSS px and 200% text zoom.
